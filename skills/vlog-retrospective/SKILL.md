# Vlog 制作复盘

按项目 AGENTS.md 和现有角色表接手。先读本技能，按需对照共享 vlog-style 和所涉岗位的当前规范。需拟写或验证技能时使用 skill-creator。交接注明实读路径与版本。

## 从反馈回到发生过的事情

确定用户指定的作品、版本、问题及最新纠正。取本期 state、log、相关时间线、cues、制作或交付回执，只读能回答这次问题的区间和字段。有已认可的旧版时，比较实际变动的镜头、声音或交付物。

按角色回执梳理每条反馈，记下用户看的版本、指出的部位、哪一版怎样改，以及实际验到哪里。区分成片交付后同一问题又被提出、交付前作废的试版、用户后来新增的偏好。用户体验、制作岗实际看听、局部抽查和技术测量分别注明。记录冲突时采用后续纠正，原因或效果证据不足时标为待核。

## 从本期事实到技能建议

区分已确认的做法、仅本期适用的参数、待试或撤回及未执行的事项。复盘分工时，检查是否改错位置、两岗是否为同一目的重复查同一源窗。策划核源词边、剪辑听最终混音，各有验收对象。比较下期同类修订时，分开记录明确认可、同一问题再提及尚未回评的反馈，另计内部改错位置的试版。节省的工时只按实际记录报告。

核对现行技能，指出哪个岗位会在哪一步改变做法。优先替换不准确或重复的条款。已有规则够用就说明沿用理由，有缺口再给目标文件、现行版本、位置、最小改写原文和理由。具体歌曲、增益、动作次数和本期时长留在当期记录。

## 给用户审阅，按确认交接

用户要看复盘或草案时，交一页可在本地打开的 HTML，给出本期事实与依据、各岗交付和建议。涉及条文修订时注明拟写原文及审批状态。独立审片由用户按需指派既有 Critic。发布数据复盘由 Analytics 按用户所给数据、平台和统计窗口办理。制作复盘直接采用现有回执，无需重复看图、试听或唤醒他岗。

用户只要草案或本次实施尚待确认时，先交待审版本。用户已明确授权本次直接更新、安装或发布时，按指定内容和操作与 Root 分工实施。由 Root 按授权更新绑定，记录实际版本及发布提交。已审、已改、已安装和已发布分别按回执说明。
